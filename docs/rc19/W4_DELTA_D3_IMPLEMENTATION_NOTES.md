# RC19 W4 Delta D3 implementation note

This branch adds a monthly Workforce incident read endpoint backed by a scoped database RPC. It aggregates the current canonical incident row by its stored `business_date`, separates review states, counts confirmed Skip/Absent/Authorized Absence/Late/Early Leave, keeps approved PASS and SWAP separate, and reports verified late minutes separately from unknown late duration. A late-minute value is projected only for a confirmed Late incident; this aggregation does not calculate or validate an arrival time itself. Detail items include source incident ID/version and shift/segment IDs; reasons and evidence references are not exposed.

Authorization is evaluated inside the `SECURITY DEFINER` RPC. Members are self-only. Leaders need the `workforce.read` permission and an active Brand scope for every returned shift; an explicitly requested Brand is rejected if the Leader has no matching scope. Admins need the effective `workforce.read` permission. The current canonical schema does not provide an agency identifier on the incident/shift/business-user rows, so this change does not invent an agency mapping. Agency-scoped aggregation remains unverified until an authoritative agency relation exists.

Report revision source snapshots are now captured by the existing `private.record_report_revision` transaction hook. Each new report revision stores the active saved D2 note IDs/versions and canonical incident IDs/versions in a private append-only row. Historical revisions are intentionally not backfilled from current notes or incidents. The existing report metrics and manual recap revision fields remain unchanged.

Internal snapshots are readable only through the authenticated versioned RPC/API and require report read plus operational-note read scope; Leaders also need `reports.read` or `reports.review`. The external projection is server-built from an explicit metric allowlist and contains no note text, personnel identifiers, incident reason, or evidence reference. Manual recap remains in the existing report revision and is not copied into the external projection because there is no separate safe-visibility field for its free text.

The new CAS/idempotency façade calls the existing `update_report` contract and stores a receipt in the same transaction as the report revision and source snapshot. A retry with the same actor/key/payload returns the original revision receipt; a changed payload conflicts. Replays re-check current report mutation permission. See `W4_DELTA_D3_REPORT_SNAPSHOT_API.md` for the typed handoff.

The PGlite test executes this migration SQL against a minimal PostgreSQL-engine fixture. It is not canonical full-schema replay, real GoTrue authentication, or authenticated integration acceptance. Apply it only after Lane 02 provides a fresh marked disposable PG17 baseline, then verify migration receipt, real Admin/Leader/Member sessions, RLS, and report workflow integration before claiming release acceptance.
